# 025 — Node 26 for every Node service

**Status:** accepted (backlog F86). Amends [ADR 017](017-mcp-gateway.md) on the gateway's runtime version.

## Context

The Node services (`apps/bff`, `apps/web`'s build, `mcp-gateway`, `mcp-accounts`, `mcp-payments`) ran on Node 22, which
has been a maintenance-only LTS line since October 2025, and the user reported problems with it. As of November 2026,
Node 26 ("Lithium") is the Active LTS line and Node 24 is in maintenance (nodejs.org release schedule). The lockfile's
dependencies all accept 26: the strictest ranges are `>=22.15.0` and `^22.22.2 || ^24.15.0 || >=26.0.0`.

## Decision

Use Node 26 everywhere: the `node:26-slim` base image in every Node Dockerfile, `node-version: '26'` in CI,
`"engines": { "node": ">=26" }`, and `@types/node` 26 at the root, forced across the graph by a pnpm override so
CopilotKit's express-family `@types` don't pull in a second major. The `engines` floor matches the types: with Node 26's
type declarations, code can call 26-only APIs and still typecheck, so a lower floor would claim support nothing tests.
Skip 24: it is already in maintenance.

## Consequences

- Contributors need Node 26 locally; the README and `docs/DEMO.md` say so.
- On Node 26, the telemetry bootstraps' `module.register()` call (the OpenTelemetry ESM loader hook) prints a DEP0205
  deprecation warning at boot. Traces still work. `import-in-the-middle`'s in-thread `registerHooks` loader was tried
  and drops the ESM `http` instrumentation, so the migration waits on upstream (backlog F87).
- Node 26 enters maintenance on 2027-10-20, when Node 27 becomes Active LTS; that is the next bump.
